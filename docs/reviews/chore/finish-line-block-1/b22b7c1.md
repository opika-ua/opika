## FINDINGS (most severe first)

1. **[medium] apps/web/src/features/reveal/useReveal.ts:80-101.** On the detail page, a real network outage still renders the generic "Щось не спрацювало на нашому боці" copy, which is the copy this commit set out to remove.
   - **Failure scenario:** `RevealFlow` calls `useReveal()` with no `ensureSession`. Every `open()` therefore runs `session.bootstrap` first. When the device is offline, that bootstrap fetch fails with a `TypeError`. `.then(([error]) => !error)` throws the error away, so `ready=false` and the hook takes the hardcoded `"loadFailed"` branch. `animals.reveal` is never called. The new `offline` branch is only reached when the network drops in the few milliseconds between bootstrap succeeding and reveal starting.
   - **Why the test misses it:** the new RevealFlow test passes only because `bootstrap.mockResolvedValue({})` in `beforeEach` makes bootstrap succeed. That is a state the real detail page almost never reaches while offline.
   - **Overclaim:** the commit body says "(detail page + deck)", and the doc comment at :21-31 makes the same claim. Both say more than the code does.
   - **Where it does work:** the deck caches a successful bootstrap in `sessionReadyRef`, so in the deck the reveal call is the first request to fail, and that path does work.
   - **Evidence:** I added a temporary probe test, ran it, then deleted it. It rejected both `bootstrap` and `reveal` with `TypeError("Failed to fetch")` and called `useReveal()` with no arguments. The assertion `reason: "offline"` came back `Received "reason": "loadFailed"`.
   - **Fix (builder's choice):** in the no-`ensureSession` branch, inspect the bootstrap error, and treat `instanceof TypeError` as `"offline"`. Add a test where bootstrap rejects with a `TypeError`. The existing bootstrap test at useReveal.test.tsx:118 uses a plain `Error`, so it does not cover this.

2. **[low] Commit body.** The body has a prose summary of the check run, not pasted `pnpm check` output, and the run left out `test:harness` and the DB suites. The builder disclosed this honestly. It is still not the evidence form the loop requires, so the PR's own check run has to be the full run.

3. **[low] apps/web/src/features/animal-detail/RevealFlow.test.tsx:250.** The offline test checks the title and the retry label. It does not check that the eyebrow «БЕЗ ЗВ'ЯЗКУ» renders, or that no body line renders. Those are exactly the two branches that change shape for this reason. Add both checks; they cost one line each.
