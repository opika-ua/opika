## FINDINGS (most severe first)

1. **[Note] `kabinet-db-scan.test.ts:158-160`: two `createRequire` forms the old regex caught are
   now missed.** The forms are `import * as nm from "node:module"; nm["createRequire"](…)` and
   `import { "createRequire" as cr } from "node:module"`. The old scan caught both, by matching the
   word inside a string. The new one reads identifiers only, so neither gives a finding. Neither
   scan catches `import { "createDatabase" as make } from "@opika/db"`.
   - Failure scenario: a reached module loads `src/api/db` through either form and the scan stays
     green.
   - Evidence: the same probe run against both scanners.
   - No live miss (both scans pass today), and both forms are deliberate obfuscation, so this is
     not a blocker. The commit's "every fail-closed rule kept" is true of the rules but not of
     these two inputs.
   - Fix (small): fail closed on any namespace or default import of `node:module` or `module`, on
     an element access whose literal key is `createRequire` or `createDatabase`, and on an import
     or export specifier whose string name is either.

2. **[Note] `test/source-ast.ts:56-71`: the scans have no time bound.** The sync API blocks in
   `readSync`, so a compiler that stays alive without answering hangs the vitest worker during
   collection, where `testTimeout` can't fire. `.github/workflows/ci.yml` sets no
   `timeout-minutes`, so GitHub's 6-hour default applies.
   - Evidence: with a stand-in binary that sleeps, `updateSnapshot` was still blocked at 12 s
     (`timeout` exit 124). With a dead one (`/bin/false`) it threw at once (EPIPE).
   - This can't be forced with the real tsgo. It is the unstable API's own property, not a
     defect in this diff.
   - Fix: a `timeout-minutes` on the CI job, or note it in D1.
