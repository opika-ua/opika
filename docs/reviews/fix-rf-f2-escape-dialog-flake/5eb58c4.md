## FINDINGS (most severe first)

No blockers.

1. [note] `docs/decisions-inbox/fix-rf-f2-escape-dialog-flake.md` RF-F2-D2 and the PR body say
   that on the detail page "nothing changes there". That's true of Escape, not of focus. The
   layout-effect heading focus also fixes the animal page: forced Escape on old code left focus
   on `BODY`, and with the fix it returns to «Написати притулку». It's a fix Oleksii would want,
   but it isn't named. Add one line to the PR's "Decisions taken" or the D3 row.
2. [note] `ContactRevealDialog.tsx:232`: capture phase moves the whole listener, the Tab trap
   included, not just Escape. That's harmless today: no element inside the dialog handles keys,
   and every Tab preventDefault happens at the same boundary as before. But a future control
   inside the dialog with its own Escape (a listbox, a nested sheet) would be pre-empted, and
   the dialog would close instead. The comment explains the Escape reason only. Optional: say
   that it covers Tab too.
3. [observation, pre-existing, out of scope] The dialog mounts only after `animals.reveal`
   resolves, so an Escape pressed while the reveal is pending still exits the deck. The reveal
   then resolves into an unmounted deck. This PR doesn't change that. Whether R3 covers the
   pending state is a follow-up question, not part of this PR.

Tests: both new tests assert unconditionally, find elements by role, label or test id, and
use no duration wait. The `setTimeout(r, 0)` yield and RTL `waitFor` polling copy the existing
sibling test; no fixed duration is waited.
