FINDINGS (most severe first)

1. **[minor-to-major, non-blocking] `packages/db/test/raw-execute-reads.test.ts` (`codeOnly`, the regex branch): a regex literal after a keyword or `=>` that contains a backtick blanks the rest of the file, and the PR doesn't record this residual.** `REGEX_MAY_FOLLOW` is a set of single punctuation characters. After `return`, `typeof`, `case`, `in`, `of`, `yield`, `throw`, `)` (`if (x) /re/`) or `>` (`=>`), a `/` is taken as division, so the regex body is lexed as code.
   Failure scenario: `export function a(s: string) {\n  return /`/.test(s);\n}` placed before `const r = await db.execute(q); return r;` in the same file. The backtick opens a template that runs to the end of the file, so the read after it is blanked and the scan passes. This is #112's bug class passing silently, and it is reproduced both raw and after `biome format` (sample s21). With a quote instead (`(s) => /'/.test(s)`, `return /'/…`, `i++ / 2; … "'"`), only the rest of that line is hidden. Biome puts the read on its own line, so those shapes are caught once formatted (s19, s31, s32).
   Exposure today: none. The only keyword-preceded regexes in scanned files (`fields.ts:145`, `compress-photo.ts:84`) contain no quote, backtick or `//`, and my dump shows they don't desync. It needs a backtick inside a regex plus a raw read later in the same file, so it is unlikely but silent and file-wide.
   Fix (small): treat `/` as opening a regex when the previous code token is one of those keywords, or `=>`. Add a test that a read after `return /`/.test(s)` is still refused. Otherwise, record it as a residual in RX-F1-D1, the doc comment and `client.ts`. Related: mutating the regex branch away (R1) leaves all 8 tests green, so regex lexing is untested.
2. **[minor] `codeOnly` mixes code points and UTF-16 units.** `const out = [...source]` splits by code point, but `blank`/`out[k]` are indexed by UTF-16 offset. After N astral characters (emoji), every blanked range moves N units right: it blanks N code characters after each comment or literal and leaves the first N characters of each blanked range unblanked.
   Failure scenario: `// 🐶🐱` above `await db.execute(sql\`TRUNCATE x\`);` makes the legitimate discard read as a violation (`[3]`, because the call's `)` is blanked). It fails loudly, not silently, in every shape I tried. Two scanned files carry one astral character each (`seed.ts`, `freshness-sentence.ts`), and neither is affected today.
   Fix: `const out = source.split("");`. I checked it in a scratch copy: the astral case passes and the whole suite stays green.
3. **[minor] The `${…}`-as-code branch is untested.** Replacing it with `false` (T1, the whole template blanked) leaves all 8 tests green. The `this.db.execute(sql\`SET x = ${(() => 1)()}\`)` case doesn't pin it, because that call is allowed either way. Without the branch, `` `${(await db.execute(q))[0]}` `` would pass. Fix: add that template-embedded read as a refused case.
4. **[nit] The two new `noTemplateCurlyInString` warnings** (lines 273 and 318; 251 predates this PR) are deliberate fixture strings. The repo has a precedent for local suppression with a reason (`apps/web/src/proxy.test.ts:691`). Add the same `// biome-ignore lint/suspicious/noTemplateCurlyInString: source text for the scanner` so the warning count doesn't drift.
