## Findings (most severe first)

1. **[Note] `docs/decisions-inbox/feat-dr1-s5-shelter-page-contract.md`, row DR1-S5-B1.** The row still
   says "waits for the coordinator's call", with status "**blocked**". The PR body records the decision
   ("My decision: it moves to S6").
   Failure scenario: the inbox is appended to the main table at merge, so the table would show an open
   blocker that has already been decided, and S6 would have no row telling it to take item 1.
   Fix: set "Default taken" to option (b), moved to S6 (the builder's and coordinator's decision,
   reversible), and set the status to "decision taken". T6 is already recorded correctly as a departure
   from §1.
2. **[Note, pre-existing, not this PR's] The harness is not isolated from a killed run's leftovers.** This
   explains the builder's "auth_organization slug duplicate" failure, and it is a real test-isolation bug,
   not noise. Three facts combine:
   - `db:seed` truncates `shelters` but deliberately leaves `auth_*` alone (`packages/db/src/seed.ts:1475`);
   - seeded shelter ids are deterministic (`shelterId(i)`, `seed.ts:738`);
   - an invitation inserts `auth_organization` with `slug: shelterId` (`kabinet-invitation-repo.ts:81`),
     and the slug is unique.

   Failure scenario: a run is stopped after a kabinet spec invited a seeded shelter, so the harness
   database is kept. The next run reseeds the same ids. The shelter reads as "without an organization"
   again, the invite inserts the same slug, and the spec fails. My single harness run started from a
   fresh database and passed 146/146.
   Fix, for a separate row: have the harness's own setup reset `auth_*` (or drop a kept harness database
   whose previous run didn't finish) before seeding.
3. **[Low] The API and Neon layers only check the positive case.** Mutation M2 (discoverable half dropped
   for a shelter scope) leaves `api.test.ts` green, and step 40 would also pass, because both use verified
   shelters only. The repository tests catch it, which is where the predicate lives, so this is not a gap
   in the guard. Adding one paused-shelter case to `api.test.ts`'s scoped block would pin T5 at the HTTP
   layer. Optional.
