## FINDINGS (most severe first)

1. **[Blocker] @better-auth/core `dist/db/adapter/factory.mjs:385`: a fallback join prints the
   raw error with `console.error(error)`, outside both seams.** With `experimental.joins` unset,
   two reads reach this path: password sign-in (`findUserByEmail(…, { includeAccounts: true })`,
   which joins the account table) and every session read (`findSession`, which joins the user).
   Failure scenario: a sign-in for an existing user while the account read fails. Evidence: in a
   scratch copy, I seeded the user and failed `select:auth_account`. The run printed
   `error: Error [DrizzleQueryError]: Failed query: … params: olena@example.org,Zq3v…,ялинка-під-вікном-1987`
   with the stack and the cause, and `expectNothingLeaked` turned red. The PR's test misses this
   because `truncateAll` leaves no user, so no join ever runs. In production, the Drizzle message
   carries the SQL and `params:` (a user id), plus whatever the driver's message head holds.
2. **[Blocker] `apps/web/src/kabinet/principal.ts:58`: a direct `auth.api.getSession` call never
   reaches `onAPIError`.** Our `hooks.before` (`auth.ts:347`, `findSession(token)`) throws the
   raw `DrizzleQueryError` to the caller. Probe: failing `select:auth_session` gave
   `thrown=DrizzleQueryError: Failed query: …`. With the real drizzle-orm error, the message is
   `Failed query: … params: <session token>`. The callers are `proxy.ts:112` (every charged
   `/kabinet` page load) and the RPC route. During a database outage, a live session token can
   therefore reach Next.js's error log. The fallback join in finding 1 prints on this path too.
   Note N1 says "none does today: better-call answers every error". That is false for `auth.api`
   calls.
3. **[Note] `auth-log.ts:50`: any object with a string `name` field is treated as an error.**
   `{ name: "Olena", email }` logs as `Olena`, and `{ name: "Kovalenko", code: "23505" }` logs as
   `Kovalenko (23505)`. This is a Latin-script display name, which is personal data but not one
   of the three values. Fix: treat only `instanceof Error` as an error.
4. **[Note] `auth-log.test.ts:38-49`: the fixture sets `name: "DrizzleQueryError"`.** The real
   drizzle-orm 0.45.2 class sets no name, so production logs read `Error (42703)`. The real
   error also carries its own `params` and `query` properties, which the fixture lacks. The
   expected line and the doc example therefore describe the fixture, not the driver.
5. **[Note] Text-rule gaps (probed):**
   - a URL-encoded address (`olena%40example.org`) passes unmasked;
   - a token of 19 characters or fewer passes;
   - a capitalised `Params:` is not cut;
   - a password in free text is not masked (already acknowledged in D1).

   Better Auth 1.6.33 has no live text path that carries these. This is low severity.

**Driver (item 6):** `sqlStateOf` reads `cause.code`. Neon's `NeonDbError` sets `code` (the
SQLSTATE), and so does postgres-js. The masking only ever emits a name and a code, so its
safety doesn't depend on the driver. No Neon smoke is needed for this change. A fix that wraps
or changes query execution would need one.

**Behaviour (item 3):**
- The body stays `""` with `content-type: application/json`.
- A refusal below 500 is not logged.
- The PW1-F4/F7 equal-work traces pass.
- No `await` was added, so timing is unchanged.

**Level (item 5):** `warn` was already Better Auth's default. The PW1-F1 lines go through
`deps.log`/`logError`, not this logger, so nothing is lost.

## STOP REASON
Findings 1 and 2 need a fix beyond the "(a) onAPIError plus Better Auth's logger" that Oleksii
chose. This is a security-scope question, so it is his call. Options:
- **(i) Recommended:** sanitise query errors at the database handle given to Better Auth. That
  means rethrowing a name-and-SQLSTATE error with no message or params. One place covers
  finding 1, finding 2 and better-call. It touches query execution, so it needs a real-Neon
  smoke.
- **(ii)** Set `experimental.joins: true`. That closes finding 1 only. It changes the SQL, so it
  needs a real-Neon smoke.
- **(iii)** Apply `pnpm patch` to @better-auth/core and add a masked catch in `principal.ts`.
  That leaves a dependency patch to carry forward.
