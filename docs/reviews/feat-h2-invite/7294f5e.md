## Findings (most severe first)

1. **[low] No bypass found.** Every traversal is either normalised by URL parsing before `proxy` sees it, so it lands on the real target and gets 403 (`/kabinet/%2e%2e/prytulkam`, `/api/auth/../rpc/gallery.list`), or Next routes it to the same exempt handler the proxy exempted. `/api/auth/..%2frpc/gallery.list` returned 503 from the auth handler, and `/api/kabinet/..%2f..%2fprytulkam` returned 503 from the kabinet handler. The proxy's pathname and Next's route choice agreed in every case. Next answers `//kabinet/../prytulkam` and trailing slashes with a 308 before `proxy` runs. Those redirects point at gated routes and serve no content. This was already the case before this change.
2. **[low] apps/web/src/api/prelaunch-gate.ts:6 is now stale.** It still says "every request 403s unless it carries the one shared secret". `proxy.ts` calls this comment "the authoritative source", and it does not mention the IN-Q1 exemption. Add one clause pointing to `isGateExemptPath`.
3. **[low] The exemption is wider than the gate's purpose. This is a follow-up, not caused by this diff.** The gate exists to save Neon transfer (prelaunch-gate.ts:14). Once production sign-in is available, `/api/auth/magic-link/verify` and `/api/auth/get-session` (`FORWARDED_AUTH_PATHS`) are reachable by bots and have no per-IP limiter. Only the sign-in POST is limited. `/api/kabinet/*` keeps its 300/min per-IP backstop. Nothing is exposed today: production answers 503 before any database access (`kabinetAuthAvailability`). The gate never rate-limited these routes, so the exemption removes nothing apart from the gate itself.
4. **[low] `/kabinet/*` now serves Next's 404 page instead of the 403.** That page includes the root layout's `<title>` ("Opika — тварини з притулків Київщини"). `X-Robots-Tag: noindex` is still sent. This is what was approved and no page content leaks.
5. **[note] The tests check both directions, as Oleksii asked.** They do not cover encoded traversal or case. Add `/kabinet/%2e%2e/prytulkam`, `/api/auth/%2e%2e/rpc/gallery.list` and `/API/auth/x` to the "still gates" list. That way a future change that decodes or lowercases the path before calling `isGateExemptPath` will fail a test.
6. **[note] Untested behaviour change.** A request to an exempt path that carries `?gate=SECRET` no longer gets the gate cookie, because the gate code never runs for that path. This is harmless, but the commit body does not mention it.
